# 软著源代码文档规范解读

## 官方原文（关键句）

> 源程序和文档应在页眉上标注相应的软件名称和版本号，右上角应标注页码，
> 源程序每页不少于 50 行，文档每页不少于 30 行。

## 逐句判定

| 要求 | 强制程度 | 说明 |
|---|---|---|
| 页眉标注软件名称和版本号 | **强制** | 唯一的常见硬性驳回点。必须与申请表软件**全称**一字不差（空格、括号、版本号写法都要对上） |
| 右上角标注页码 | 中等（「应」） | 页脚页码是通行做法，被挑的概率低；要完全对齐原文就放页眉右上角 |
| 源程序每页 ≥ 50 行 | **强制** | 「行」指**有效代码行**。结束页可少于 50 行 |
| 文档每页 ≥ 30 行 | **强制** | 指软件说明书/用户手册，与源代码文档是两份材料 |

## 提交份量

- **不足 60 页**：全部提交。
- **超过 60 页**：提交【**前 30 页 + 后 30 页**】，本地留存完整源码。
- **不要**靠缩小页边距把页数硬压到 60 页以内——会造成文字贴边，反而被挑。

「60 页」是**提交份量**，不是文档页数上限。

## 「每页 50 行」到底怎么算

这是最容易出错的一条，涉及三个口径：

1. **逻辑行**：源码文件里的行数（1 个换行 = 1 行）。
2. **物理行 / 视觉行**：Word 渲染后实际占用的行，**长行折行会变成 2 行以上**。
   PDF 里数到的是这个。
3. **行号口径**：文档若显示行号，行号递增的值。

三者关系：物理行 ≥ 逻辑行（长行折行）；行号通常等于物理行。

**审查方看的是每页实际有多少行**，所以：

- 长行多的文档，逻辑行数会低估页数。
- 用 PDF 逐页数（脚本里 `_pdf_lines_per_page`）最接近真实。
- 数的时候要**排除页眉、页码、以及左侧的行号残留数字**（否则每页会虚高
  一倍左右——页眉和页码会被当成两行内容）。

估算每页行数的公式：

```
每页行数 ≈ (页高 − 上边距 − 下边距 − 页眉页脚挤压) / 行距
```

页眉页脚挤压无法精确预知，必须实测。

## 常用排版参数

| 项 | 推荐值 | 说明 |
|---|---|---|
| 正文字体 | 宋体 | 必须含中日韩字形；Courier New 不含中文会回退 |
| 正文字号 | 五号（10.5pt，`w:sz="21"`） | 同时写 `w:sz` 与 `w:szCs` |
| 行距 | 固定值 13.0~13.5pt | 固定值避免跨软件漂移 |
| 页边距 | 上下 2.0~2.54cm，左右 2.0~3.17cm | 过窄（<1.5cm）易判贴边 |
| 行号 | **关闭** | 非源码内容，且会压缩正文宽度 |
| 页码 | 页眉右上角 | 或页脚居中（通行） |

## 常被问到的问题

**Q：第一页行数和其他页不一样，有问题吗？**
没问题。

**Q：第一行是空行可以吗？**
不违规，但不专业且浪费版面，建议删。

**Q：HTML / Vue 里的 `<style>` 块算代码吗？**
算。SFC 组件的 `<template>` / `<script>` / `<style>` 都是源码的一部分。
要注意的是别把**提取时混入的脚手架**（重复的 `<!DOCTYPE html>` 外壳）当成代码交上去。

**Q：Windows COM 接口声明（`_ICreateDevEnum` 之类）要不要删？**
不删。软著看的是源代码文件本身，只要是你组织/编写的就在保护范围内。
判断依据是它是否与业务逻辑咬合——如果 `_enumerate()` 这类**你自己的**函数
依赖这些声明才能运行，删了就跑不起来。

**Q：代码里出现真实邮箱 / 手机号怎么办？**
源码中不得出现作者信息。功能性的收件人配置建议**清空值**而不是删整行
（保留对象结构，最小改动）。

**Q：代码里散落的 `/** 2025-09-14 */` 是什么？**
多为编辑器自动插入的日期注释，属噪音，建议删除。

**Q：包名 / 域名 / 本地 IP 要删吗？**
不需要。`127.0.0.1`、`localhost`、业务域名都是正常的代码内容。
